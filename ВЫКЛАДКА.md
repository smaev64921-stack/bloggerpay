# Выкладка BloggerPay

Что лежит рядом и зачем.

| Файл | Зачем |
|---|---|
| `bloggerpay-1008-v100.html` | само приложение; на хостинг уезжает как `index.html` |
| `onboarding.html` | знакомство при первом входе (4 экрана-сторис); лежит рядом с приложением |
| `privacy.html` | политика конфиденциальности; её адрес спрашивают Google и TikTok |
| `sw.js` | офлайн-режим и кэш; **обязан лежать рядом**, иначе приложение просто работает без офлайна |
| `netlify.toml` | заголовки: свежесть главной страницы, защита от встраивания чужими сайтами |
| `logo.jpg` | знак BloggerPay в письме с кодом; без него в письме будет пустой квадрат |

Прежние версии лежат в папке `версии/` — точки отката, на сервер их класть не нужно.

## 1. Перед выкладкой: бот и мини-апп

Без этого пригласительные ссылки, партнёрская программа и кнопки «Поделиться» ведут в никуда.

1. В Телеграме открыть **@BotFather** → `/newbot` → задать имя и адрес бота.
2. Там же `/newapp` → выбрать бота → задать **короткое имя мини-аппа** и указать адрес сайта.
3. Открыть приложение → **Админ-панель** (кнопка на экране регистрации) → **Настройки платформы**.
4. Заполнить два поля внизу формы: имя бота без `@` и короткое имя мини-аппа. Сохранить.
5. Токен бота из BotFather вписать в `server/.env`, строка `BOT_TOKEN=`. После этого
   заработает вход по Телеграму — человеку не нужно будет придумывать пароль.

Пока это не сделано, приложение честно предупреждает: красная строка на дашборде админки и сообщение в консоли браузера. Пользователю оно не показывается.

Проверить из консоли: `bpLinkReady()` → должно стать `true`, `bpInviteLink()` → должна получиться ваша ссылка.

**Тревога в Телеграм.** Чтобы скрытые ошибки сайта прилетали вам сообщением, в `server/.env` рядом с `BOT_TOKEN=` заполните `ADMIN_CHAT_ID=` — числовой id вашего чата (узнать: написать @userinfobot). Затем один раз нажмите Start у своего бота. После перезапуска сервера в консоли появится строка «тревога: ошибки уходят в Телеграм». Подробности: `server/README.md`, раздел «Тревога в Телеграм».

## 3. Что проверить сразу после выкладки

Это те места, которые невозможно проверить локально.

- [ ] **Service worker зарегистрировался.** Открыть сайт в обычном браузере → DevTools → Application → Service Workers. Должен быть активен `sw.js`. Если нет — смотреть ошибку в консоли; приложение при этом работает, но без офлайна.
- [ ] **Обновление доезжает.** Выложить правку, перезагрузить дважды. Новая версия должна появиться со второго раза, а не через сутки. Если застряло — проверить заголовок `Cache-Control` на `index.html`.
- [ ] **Мини-апп открывается внутри Телеграма** по ссылке из BotFather, а не только в браузере.
- [ ] **Заставка уходит.** На медленном интернете видна заставка «BloggerPay», потом экран входа. Если заставка висит дольше 15 секунд — это аварийный предел, значит приложение не запустилось.
- [ ] **Вход держится.** Закрыть мини-апп полностью и открыть заново — экрана входа быть не должно.
- [ ] **Выгрузка файлов.** В мини-аппе на телефоне нажать «Экспорт данных»: файл в «Загрузки» не попадёт — должно открыться окно с содержимым и кнопкой «Скопировать всё». В браузере телефона та же кнопка должна скачать файл.

## 3½. Боевой запуск: чек-лист

Порядок, после которого можно звать людей. Каждый шаг обязателен.

**1. Сервер-касса на VPS (любой хостинг с Node 22.5+).**

```
git-архив папки server/ → на сервер
cd server && node server.js        # или через pm2/systemd, чтобы жил после перезагрузки
```

Наружу сервер выставляется только через HTTPS. Проще всего — Caddy
(автоматический сертификат), файл `Caddyfile`:

```
kassa.вашдомен.ru {
    reverse_proxy 127.0.0.1:8090
}
```

**2. `server/.env` — боевые значения:**

- `ADMIN_KEY` — длинная случайная строка (никому и никуда);
- `ORIGIN=https://адрес-сайта-на-netlify` (не `*`!);
- `PUBLIC_URL=https://kassa.вашдомен.ru`;
- `BOT_TOKEN` — токен бота из BotFather (включает вход по Телеграму);
- `TEST_TOPUP=0` — тестовое пополнение на бою ВЫКЛЮЧИТЬ;
- `TRUST_PROXY=1` — обязательно за Caddy/nginx, иначе не работает
  ограничение частоты (защита от перебора паролей);
- когда будет договор с ЮKassa: `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`,
  `PAY_RETURN_URL=https://t.me/<бот>/<апп>` — и пополнение станет настоящим,
  а тестовое выключится само;
- почта (восстановление пароля): `RESEND_API_KEY` из кабинета resend.com,
  `MAIL_FROM` — адрес на **подтверждённом** домене (Resend → Domains, записи
  SPF и DKIM), `MAIL_DEBUG` — пусто или `0`. Тестовый `onboarding@resend.dev`
  на бою не годится: письма с него доходят только владельцу аккаунта Resend,
  идут с задержкой в минуты и падают в «Спам». Подробный разбор и порядок
  действий — в `ПОЧТА-НАСТРОЙКА.md`.

**2½. Бот с кнопкой «Открыть».** Запускается отдельно от кассы:

```bash
node server/bot.js
```

В `.env` для него нужны `BOT_TOKEN` (от @BotFather) и `APP_URL` — адрес
сайта с приложением по https. После запуска у бота на `/start` появляется
синяя кнопка и постоянная кнопка меню рядом с полем ввода. Держите его
живым так же, как кассу (systemd или pm2) — это два разных процесса.

**3. Адрес сервера в приложении.** Если сайт раздаёт сама касса (так устроен
запуск на хостинге бота: `node server/server.js` отдаёт и сайт, и API), делать
ничего не нужно — приложение берёт адрес страницы. Если сайт лежит отдельно
(статический хостинг), укажите адрес кассы в блоке `<script id="bp-config">`
в начале файла:

```
window.BP_SERVER = 'https://kassa.вашдомен.ru';
```

Без сервера деньги у людей останутся локальными игрушками в браузере.

**4. Выложить приложение** (раздел 2 ниже) и заполнить имена бота и
мини-аппа в админке (раздел 1).

**5. Проверить руками:**

- [ ] `https://kassa.вашдомен.ru/api/health` отвечает `{"ok":true}`;
- [ ] вход в мини-апп → на балансе серверные нули, а не старые локальные числа;
- [ ] пополнение: с ключами ЮKassa — открывается страница оплаты, после
  оплаты сумма сама появляется на балансе; без ключей и с `TEST_TOPUP=0`
  кнопка честно говорит «пополнение недоступно»;
- [ ] вывод: заявка появляется в админ-панели `/admin`, после «выплачено» статус
  доезжает в приложение;
- [ ] верификация: фото паспорта доходит до раздела «Верификация» в
  `/admin`, решение доезжает до человека;
- [ ] восстановление пароля: «Забыли пароль?» → письмо с кодом приходит
  (проверьте и папку «Спам»), код меняет пароль, старый больше не пускает;
- [ ] сверка в `/admin` зелёная.

**6. Откуда деньги.** Сервис зарабатывает комиссию 4% с каждого вывода
(смотрите плитку «Доход сервиса» в `/admin`). Ваша ежедневная рутина:
проверять верификации, переводить выплаты и отмечать их, разбирать споры.

## 4. Два режима: без сервера и с сервером

Приложение умеет работать двумя способами, и это важно понимать.

**Без сервера** (просто выложенный файл). Все данные лежат в браузере
пользователя. Двое разных людей не увидят друг друга, деньги ненастоящие —
на каждом экране висит полоса «Тестовый режим». Годится, чтобы показать
продукт и потрогать сценарии, но не чтобы работать с людьми.

**С сервером** (запущена папка `server/`). Деньги считаются на сервере,
пользователь их переписать не может; заявки на вывод попадают в реестр, где
вы их видите и отмечаете; споры делит оператор. Включается само, когда сайт
раздаёт касса; для отдельного хостинга — ключ `bp_server_url` или
`window.BP_SERVER`.

## 5. Что осталось сделать до настоящих денег

- **Договор с ЮKassa.** Код приёма платежей готов (создание платежа,
  страница оплаты, вебхук, автопроверка статуса, зачисление через журнал) —
  осталось получить ключи в кабинете yookassa.ru и вписать их в `.env`.
  Для договора нужен статус ИП или юр. лицо.
- **Правовая часть.** Кто вы по закону и на каком основании держите чужие
  деньги (оферта, агентская схема или номинальный счёт). Без этого
  провайдер ключи не выдаст.
- **Токен бота** в `server/.env` — чтобы заработал вход по Телеграму.
- **Ключи TikTok и YouTube** — чтобы блогеры подтверждали владение каналом.
  Код готов и проверен, нужна только регистрация приложения в кабинете
  каждой площадки: см. `ПОДКЛЮЧЕНИЕ-СОЦСЕТЕЙ.md`. Без ключей приложение
  честно говорит, что проверка не настроена, и работает дальше.

Полный разбор и план — в `документы/АУДИТ-ЗАПУСК-v89.md`. Часть его уже
сделана; как справочник по тому, что и почему чинили, он остаётся полезным.

→ в панели bothost.ru кнопка «Обновить из Git» у бота
`bot_1788290165_4956_sudarevivan` → сверить, что живой файл совпал с
локальным. Сборка около полутора минут, сайт в это время недоступен.

чтобы площадки не отозвали подтверждение сайта.
